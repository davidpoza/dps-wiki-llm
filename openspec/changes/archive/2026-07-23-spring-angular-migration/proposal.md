## Why

`dps-wiki-llm` today is a set of deterministic Node.js/TypeScript CLI tools orchestrated by self-hosted **n8n**, with retrieval split across SQLite FTS5 and a local ONNX vector index, and a Telegram bot wired through n8n polling. That model couples business logic to n8n, spreads state across ad-hoc files, and offers no first-class UI or real-time visibility into long-running jobs (ingest, embedding, answer synthesis).

This change migrates the platform to the team's standard stack — proven in `../dog-booking-planner` — **Spring Boot 3.3.x / Java 21 + PostgreSQL 17 + Angular 21 (signals) + RabbitMQ + Docker Compose behind nginx** — so the system becomes a single deployable application with a durable job queue, real-time job progress over SSE, and OpenAI-compatible LLM calls via **Spring AI**. n8n is removed and the Telegram bot is re-hosted in the backend. This foundational change delivers the scaffold plus the two core flows (ingest and answer); feedback propagation, maintenance, and the full frontend follow in later changes.

## What Changes

- **NEW** Spring Boot 3.3.x backend (Java 21, Maven) with the reference project's layout (`config`, `controllers`, `services`, `repositories`, `domain`, `dto`, `mappers`), Flyway migrations, Actuator health, JWT-ready security config, springdoc/OpenAPI, MapStruct + Lombok.
- **NEW** PostgreSQL 17 as the single datastore for indexes, jobs, and operational state, with the **pgvector** extension for **semantic (vector) search**. **BREAKING**: retrieval is embeddings-only — the previous SQLite FTS5 lexical leg and the `0.6·semantic + 0.4·lexical` hybrid fusion are dropped in favor of pure nearest-neighbor search (no keyword/BM25 path).
- **NEW** RabbitMQ durable job queue: a **serialized write consumer** (`prefetch=1`, single consumer) for state-mutating jobs (ingest) and a **separate read/answer queue**, with retries and a dead-letter queue. REST enqueues jobs and returns `202 Accepted`.
- **NEW** **Server-Sent Events** progress channel (`GET /api/jobs/events`) broadcasting the full job lifecycle (`QUEUED → STARTED → PROGRESS → COMPLETED → FAILED`) to subscribed clients, ported from the `SolverQueueService`/`SseEmitter` pattern. nginx disables buffering on the SSE path.
- **NEW** **Spring AI** integration (OpenAI-compatible clients): **chat completions** against the gateway (provider-switchable base URL / model / API key, replacing `tools/lib/llm.ts`, with retry/backoff on 429/5xx) and **embeddings** against a **local embeddings sidecar** (HuggingFace TEI / Ollama serving `multilingual-e5-small`, 384 dims, replacing `@xenova/transformers`) — local/offline on the Compose network, no external dependency, and no ONNX/DJL weight inside the backend.
- **NEW** Angular 21 frontend (standalone components, **signals-based** state, PrimeNG, pnpm), **fully responsive / mobile-ready**, served behind nginx. It provides: a **job viewer** with live phases, per-file traversal, and errors (over SSE); a **chat** over the knowledge base; a **multi-format ingest** UI (markdown + links; PDF deferred); a **guided connection-review** UI; and a **job revert** action.
- **NEW** **Guided ingestion**: after connection discovery (LLM-proposed links + semantic neighbors), an ingest runs either **unattended** (auto-apply) or **validated** — pausing in an `AWAITING_REVIEW` state to present candidate connections as accept/reject checkboxes plus a **lexical file picker** (`pg_trgm`) for manual selection; accepted connections are applied directly to the knowledge files. The baseline source note is always applied; guided review is available for any ingest job.
- **NEW** **Job revert**: a completed job can be reverted, undoing **both** the git knowledge base (a git revert of the job's commit range) **and** the database (compensating row changes), with conflict detection when a later job touched the same files.
- **NEW** Backend-hosted **Telegram bot** (long polling) that routes `/ask` and `/ingest` commands onto the job queue and streams results back, replacing the n8n Telegram workflow.
- **PRESERVED** The git-backed **markdown vault** and the hard `raw/` → `wiki/` boundary. The backend mounts the vault volume; only `raw/**` triggers ingest, `wiki/**` stays derived state. Mutation application keeps idempotency keys, the topic-creation guard, and per-operation git commits + change-log provenance.
- **BREAKING** **n8n is removed** as the orchestrator: workflows under `n8n/`, the runner image, and n8n-specific docs/env are retired. Orchestration moves into the Spring Boot backend + RabbitMQ.
- **BREAKING** The Node.js CLI toolchain (`tools/`) stops being the runtime entry point; its behavior is ported into backend services. The existing tools remain as a reference/oracle during the migration but are no longer the deployed system.

## Capabilities

### New Capabilities
- `platform-foundation`: Dockerized Spring Boot + Angular + PostgreSQL + RabbitMQ + embeddings-sidecar scaffold behind an nginx proxy — Flyway migrations, config/env model, Actuator health, CORS, OpenAPI, and the Angular signals shell.
- `vault-git-store`: Git-backed markdown vault access layer — safe vault-scoped path resolution, frontmatter/section-merge markdown rendering, idempotent mutation application with the topic-creation guard, and per-operation git commits with change-log provenance.
- `llm-integration`: Spring AI OpenAI-compatible clients for chat completions (gateway) and embeddings (local sidecar) — provider-switchable configuration, retry/backoff, and JSON-response extraction helpers.
- `semantic-retrieval`: pgvector semantic (vector) search over `wiki/**` — a `documents` index plus incremental embedding via the **local embeddings sidecar** (`multilingual-e5-small`, 384 dims) and top-k nearest-neighbor retrieval by cosine distance. No lexical/FTS leg in RAG; a lightweight `pg_trgm` file lookup serves the manual connection picker only.
- `job-queue-and-progress`: RabbitMQ durable queues with a serialized write consumer and a read consumer, a persisted job lifecycle (including `AWAITING_REVIEW` and `REVERTED`), retries + dead-letter handling, and SSE broadcasting of job progress and per-file events.
- `ingest-pipeline`: Backend ingest flow — intake (markdown upload / link fetch into `raw/**`), normalize, LLM-clean into a source note, apply the baseline plan, reindex, commit, then discover/guardrail connections and apply per the ingest mode, emitting progress and file events over SSE.
- `guided-ingestion`: Connection discovery (LLM-proposed + semantic neighbors) with `unattended` vs `validated` modes — the review contract (accept/reject candidates + manual `pg_trgm` picker) applying accepted connections directly to the knowledge files.
- `job-revert`: Revert a completed job across git (git revert of its commit range) and the database (compensating row changes), with conflict detection and its own auditable operation.
- `frontend-experience`: Responsive PrimeNG app — job viewer (phases/files/errors), chat over the KB, multi-format ingest UI, guided connection-review UI, and job revert.
- `answer-pipeline`: Backend answer flow — semantic retrieval → bounded context packet → LLM synthesis → answer record artifact, emitting progress over SSE (feedback evaluation is stubbed for a later change).
- `telegram-bot`: Backend Telegram long-polling bot that authorizes an allowed chat, routes `/ask` and `/ingest` onto the job queue, and returns results, replacing the n8n polling workflow.

## Impact

- **New services / infra**: `backend/` (Spring Boot), `frontend/` (Angular), `docker/nginx.conf`, root `docker-compose.yml` (postgres + pgvector, rabbitmq, **embeddings sidecar** [TEI/Ollama], backend, frontend, nginx proxy), Flyway migrations under `backend/src/main/resources/db/migration`.
- **Datastore**: PostgreSQL 17 with `pgvector`; new tables for documents, embeddings, jobs, and operations/audit. SQLite `state/kb.db` and `state/semantic/` are superseded.
- **Dependencies added**: Spring Boot starters (web, data-jpa, amqp, actuator, validation, security), Spring AI (OpenAI-compatible **chat + embeddings** clients), a **local embeddings sidecar image** (HF TEI / Ollama serving `multilingual-e5-small`/384), pgvector, `pg_trgm` (manual file lookup), a link/HTML fetch+extract library (e.g. jsoup), Flyway, MapStruct + Lombok, springdoc, **TelegramBots v8** long-polling starter; Angular 21 + PrimeNG + pnpm.
- **Dependencies removed**: n8n (+ runner image + workflows), `@xenova/transformers`, `@opendocsg/pdf2md`/`pino` runtime path (superseded by backend equivalents), and the Node CLI runtime as the deployed entry point.
- **APIs**: new REST surface under `/api/**` — enqueue ingest (markdown upload / link) and answer jobs, job status, `GET /api/jobs/events` SSE, candidate-connection review submit, manual `pg_trgm` file lookup, and job revert — plus OpenAPI docs and backend Telegram polling. n8n workflow JSON and the n8n Docker/runbook sections are retired.
- **Preserved contracts**: the markdown vault layout, `raw/`→`wiki/` boundary, mutation-plan / source-payload / answer-record JSON shapes, idempotency keys, topic guard, and git provenance carry over into the backend.
- **Out of scope (later changes)**: PDF and YouTube extraction (markdown + link ingestion are in scope), answer-side feedback propagation (`KB - Apply Feedback`; note the *ingest*-side connection review is in scope via `guided-ingestion`), maintenance flows (lint / health-check), and term-topic-resolution / concept-dedup re-implementation.
